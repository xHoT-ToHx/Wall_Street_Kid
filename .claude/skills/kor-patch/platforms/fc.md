# FC (패미컴 / NES)

## 하드웨어 요점
- CPU 6502 (2A03), 롬은 `$8000-$FFFF` 에 매퍼로 뱅크 스위칭. iNES 헤더 16바이트(+trainer 512) 뒤에 PRG, 그 뒤 CHR.
- PPU 타일: **2bpp, plane0 8바이트 → plane1 8바이트** (`fc2bpp`). 패턴테이블 2개 × 256타일.
- CHR-ROM 게임: 폰트가 CHR 뱅크에 고정 → 한글 타일을 넣으려면 CHR 뱅크 여유/스위칭(MMC1/MMC3 CHR 뱅킹)을 이용하거나 CHR-RAM 전환.
- CHR-RAM 게임(헤더 chr_rom=0): 폰트를 PRG 에서 업로드 → 동적 로딩 구현이 비교적 쉬움.
- VRAM 쓰기는 VBlank 중에만(렌더링 off 제외). 프레임당 안전 전송량 작음(≈100~160바이트 수준, NMI 루틴 여유에 따라).

## 주소 변환 (spec.json)
- 16KB 뱅크(MMC1/UxROM 등): `{"type":"linear","cpu_base":"0x8000","file_base":"0x10 + bank*0x4000","window":"0x4000"}`
- 8KB 뱅크(MMC3): cpu_base 는 뱅크가 매핑된 창($8000/$A000/$C000), window 0x2000.
- 고정 뱅크(마지막 뱅크 $C000/$E000)도 같은 방식.

## 텍스트 엔진 특징
- 1바이트 코드, 가나 약 64~90자 + 탁점은 별도 타일(윗줄) 방식 많음.
- 대사창 8x8 셀, 줄당 12~28자. 탁점이 윗줄에 찍히는 게임은 2줄 단위 레이아웃.

## 한글 폰트 전략
1. **8x16 세로 2타일 한글** + 동적 로딩: 가장 흔한 성공 패턴. 줄 수가 절반이 되므로 대사창 레이아웃 조정.
2. 8x8 한글: 판독성 낮음. 메뉴/고정 필드에서만 제한적으로.
3. CHR-ROM + 여유 CHR 뱅크: 빈도 상위 수십~백여 자 고정 배치 + 대사 시 CHR 뱅크 전환.
4. 매퍼 교체(MMC3/MMC5, CHR-RAM 보드)는 마지막 수단 — 에뮬레이터/실기 호환성 리스크 보고.

## 확장
- 매퍼별 PRG 최대 크기 확인 (MMC1 512KB(SUROM), MMC3 512KB, UxROM 256KB(UOROM)...). 확장 시 헤더 PRG 개수 갱신, CHR 이 뒤로 밀리는 점 주의(CHR 오프셋 재계산).

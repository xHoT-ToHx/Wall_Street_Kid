## 0. 결론 요약
- 롬: UOROM 256KB(16뱅크), 매퍼 2 유지. 고정 뱅크 7 → 15, 버스충돌 표 $F07E(0-6) → $FE90(0-15). 헤더 PRG 8→16.
- 문자 코드: 1바이트 원본(00-36 문자, 49 공백, 80|c 문자+공백, FB-FF 제어) 그대로 + **2바이트 한글 `5x yy`(리드 0x50-0x5F)** = 글리프 번호 `(x<<8|yy)` (font-engineer 잠정 코드 0x5000+번호와 동일). 리드 0x4F = 원거리 점프(문자열이 다른 뱅크로 이어짐).
- 글리프: 8x16(위/아래 타일), 대사창 2행 피치 그대로. 동적 업로드(문자 1개 출력 = NMI 1회, 그 NMI 에서 글리프 32B 업로드 후 네임테이블 기록).
- 타일 공간: BG 테이블 $0000 은 꽉 참 [확인] → **대사창 구간만 BG 패턴테이블을 $1000(스프라이트 테이블)로 전환** (스프라이트0 히트 분할). $1000 은 스프라이트가 0x00-0x1E 만 사용 [확인, 랄프 전화 장면].
- 텍스트 뱅크: bank4 → 12, bank6 → 13 으로 통째 복사 후 한글 삽입, `$D7B6` 진입에서 뱅크 번호 4→12, 6→13 치환. 넘치는 문자열은 넘침 뱅크(11,14)에 두고 원래 자리에 4바이트 점프 스텁.

## 1. 원본 엔진 조사 [정적/확인]
- `$D7B6`(A=텍스트 뱅크, FF=현재) → `$D7DF` → 루프 `$D867`, 문자 취득 `$D8F8`(포인터 $81/$82, 결과는 버퍼 ($89) 에 1바이트, 전진량 $7B=1/2).
- 출력: 타자 모드($7A bit7=0)는 글자마다 `$D936` 이 레코드 $0323=[82][w=1][rows=1][FF][2B 03][PPU lo hi] 를 만들고 `$F302` 로 NMI 1회 작업 예약 + `$F03E`(NMI 대기). 이어쓰기 모드(bit7=1)는 줄 단위(w=$78).
- PPU 큐 레코드 8B: cmd(bit0-1: 1읽기/2쓰기/3채우기, bit6 +32증가, bit7 사각형[w x rows]), count lo/hi, bank(FF=현재), src, dst. NMI 의 $0B/$0C 1회 작업으로 1레코드 처리.
- 스크롤 `$D9DB`: 2행 피치면 2행씩 읽어 2행 위로 다시 씀(빈 행 포함) → 8x16 아래 타일도 함께 스크롤됨 [정적]. 창 지우기 `$DA62` 는 높이만큼 모든 행 지움.
- 뱅크 전환 `$F066`: `$F03E`(NMI 대기) 후 $08←$07, $07←A, `STA $F07E,X`. NMI 큐 작업은 레코드 bank 로 `$F8EC` 전환 후 $26(=$07) 복원.
- NMI `$F95C`: OAM DMA($06≠0) → $0B 1회 작업 → $09 매프레임 훅 → `$DE67`(사운드) → 카운터, $05=0.
- PPUCTRL 섀도 $01 (BG $0000, SPR $1000). 스크롤 섀도 $03/$04.
- 스프라이트 할당기($F540-$F72x)는 슬롯 1-63 사용, **슬롯 0 미사용** [확인: 랄프 장면 OAM]. A 버튼 표시도 스프라이트(슬롯21, 타일 1E, y=214).
- 고정뱅크 빈 공간 $FE90-$FFDD(334B)만 존재 [정적].

## 2. 타일 예산과 분할(split) [설계]
- BG $0000: 0x00-0x36 영문 폰트, 0x37-0x40 기호(패스워드), 0x41-0x48 테두리, 0x49 공백, 0x60-0xFF 장면 그림. 랄프 장면 빈 타일 5개뿐 [확인].
- SPR $1000: 0x00-0x17,0x1A-0x1E 사용, 나머지 227 빈 타일 [확인].
- 방식: 매 프레임 NMI 끝에서 스프라이트0 히트를 기다렸다가 `$2000 = $01|$10`(BG=$1000). 다음 NMI 시작에서 $01 로 복귀.
  - 스프라이트0: 슬롯0, $1000 타일 0x4A(왼쪽 위 1픽셀), 우선순위 뒤(attr $20), 행16 의 오른쪽 정보창 아래 테두리(타일 0x47, 픽셀행1-6 불투명) 위 x=200, y=128 → 스캔라인 129 에서 히트, 행16 이하가 $1000.
  - 행16 이하 화면에 쓰이는 원본 코드 0x41-0x49(테두리·공백)는 $1000 같은 번호에 사본을 둔다. 엔진이 쓰는 1바이트 문자(<VAR> 숫자·기호)는 사본 위치로 치환.
  - 히트가 안 오면(창 레이아웃 다름·렌더링 꺼짐) 시간 제한 후 포기(분할 없음, 멈춤 없음).
  - 비용: 분할 활성 중 NMI 가 스캔라인 ~129 까지 대기(프레임 CPU 약 55%). 대사 표시 중에만 활성.
- $1000 배치(설계안):
  | 타일 | 용도 |
  |---|---|
  | 0x00-0x1F | 게임 스프라이트(예약) |
  | 0x20-0x3F | 한글 슬롯 B (16쌍, 마지막에 사용) |
  | 0x41-0x49 | $0000 테두리·공백 같은 번호 사본 |
  | 0x4A | 스프라이트0 점 |
  | 0x4B-0x5B | <VAR> 용 1바이트 문자 사본(숫자·$ , . / : % - 등 17) |
  | 0x5C-0xFF | 한글 슬롯 A (82쌍) |
  → 동시 표시 한글 최대 98자(슬롯 A+B). 번역 실측(구간당 고유 ≤90)을 수용.
- 활성: 창(y≥17)에 한글 첫 글자를 쓸 때 사본 업로드(NMI 당 64B, 약 7프레임) 후 활성. 비활성: 렌더링 끔(장면 전환) 시.

## 3. 슬롯 할당 [설계]
- 캐시: 슬롯→글리프 번호(lo/hi 배열). 적중 시 재사용, 미스 시 원형 순서로 다음 슬롯(가장 오래 전 할당) 덮어씀.
- 초기화: 창 지우기($DA62, <PAGE>)와 분할 비활성 시.
- 정확성 조건: 화면에 보이는 글자의 슬롯이 덮이지 않을 것 → 빌드 검사기(asm/tools/pack_text.py --check)가 창 모델(줄바꿈·스크롤·<PAGE>)로 할당을 모의해 위반 문자열을 보고.

## 4. 문자 코드 / 폰트 인터페이스 [설계]
- 1바이트: 원본 그대로(번역문 속 ASCII 는 8x16 글리프로 쓰는 게 기본. 1바이트 원본 문자는 <VAR> 출력용).
- 2바이트: 리드 0x50-0x5F, 둘째 바이트 00-FF → 글리프 번호 n = (리드-0x50)*256 + 둘째 (최대 4096).
- 0x4F bb ll hh: 문자열이 뱅크 bb 의 $hhll 로 이어짐(패커가 넘침 처리에 사용).
- 폰트 데이터: build/font.bin(1bpp, 16B/글리프: 위 타일 8B → 아래 8B). 뱅크 8+(n>>10), 주소 $8000+(n&$3FF)*16. 3뱅크=3072자 수용.
- 업로드 시 plane1=0 으로 2bpp 32B 변환.

## 6. 조사 메모
- RAM: $0560-$079F 는 랄프 장면에서 0. 정적 참조 없음은 $0580-$05FF. $0600 페이지는 bank0/1 코드가 버퍼로 사용($0600,Y). 스택 하한 관측 $01B8.
- 카나리(A5) 시험: $0100-$017F, $0560-$0744 — 사무실 화면 진입까지 변화 없음 [확인, 짧은 구간].

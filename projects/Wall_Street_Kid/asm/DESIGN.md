# 한글 엔진 설계 — Wall Street Kid (FC, UxROM → UOROM 256KB)

작성 asm-hacker. 표기: [검증] 에뮬 확인 / [구현] 빌드에 들어감, 미검증 / [설계] 미구현 / [추정].
소스 `asm/kor_engine.asm`, 도구 `asm/tools/{asm65,expand,kor_build}.py`, 훅·빈 공간 `asm/CHANGES.md`.
빌드: `PYTHONPATH=<워크트리>/tools PYTHONUTF8=1 python -m romkr build projects/Wall_Street_Kid` (project.json `commands`, `insert_scripts:false`).

## 0. 결론
- 매퍼 교체 없음: 매퍼 2 그대로 PRG 128→256KB(UOROM). 고정 뱅크 7→15, 버스충돌 표 $F07E(0-6)→$FE90(0-15). [검증]
- 대사창: 8x16 한글(위·아래 타일), 2행 피치 대사창에 그대로, **줄당 28자(칸=글자)**. [검증: 래리 소개, <WAIT> 스크롤]
- 타일 공간: BG 테이블 $0000 은 꽉 참 → **대사창 윗행부터 화면 아래까지 BG 패턴테이블을 $1000(스프라이트 테이블)으로 분할**. 분할 시점은 **스프라이트 오버플로 플래그**(감지 스프라이트 9개)로 잡는다(스프라이트0 히트는 창 위에 불투명 BG 픽셀이 필요해 장면마다 달라 기각). [검증]
- 동시 표시 한글 **107자(슬롯)**, 원형 할당 + 모의 검사. 번역 실측(구간당 고유 ≤90)을 수용, 현재 번역 전체 위반 0.
- 텍스트: bank4→12, bank6→13 통째 복사 후 한글 삽입, `$D7B6` 의 뱅크 인자 4→12, 6→13 치환. 넘치면 `4F bank lo hi` 점프. 현재 넘침 0 (12: 14,774/15,992B, 13: 10,741/11,640B).

## 1. 원본 엔진 요점 [정적/검증]
- `$D7B6`(A=텍스트 뱅크, FF=현재) → `$D7DF` → 루프 `$D867`, 문자 `$D8F8`(포인터 $81/$82 → 버퍼 ($89), 전진 $7B).
- 타자 모드($7A bit7=0): 글자마다 `$D936` 이 레코드 $0323=[82][w=1][rows][FF][$032B][PPU] 를 `$F302` 로 예약 + `$F03E`(NMI 대기). 이어쓰기 모드(bit7=1)는 줄 단위.
- PPU 큐 레코드 8B: [cmd(bit0-1 1읽기/2쓰기/3채우기, bit6 +32, bit7 사각형)][256B 페이지 수][나머지][bank FF=현재][src][dst lo][dst hi]. NMI 1회에 1레코드. `$F302` 는 BG 꺼짐이면 메인 스레드에서 즉시 실행(이때 `$F8EC` 가 $07 없이 뱅크를 바꿈).
- 스크롤 `$D9DB` 는 2행 피치면 2행씩(빈 행 포함) 복사 → 8x16 아래 타일도 함께 스크롤 [검증].
- NMI `$F95C`: OAM DMA → $0B 작업 → $09 프레임 훅 → `$DE67` 사운드 → $05=0. PPUCTRL 섀도 $01, PPUMASK 섀도 $02, 스크롤 $03/$04.
- **원본 폰트는 plane1 만 사용(색 2)**. analysis.md 의 "plane1=0" 은 반대였다 [검증].
- 메인 스레드가 VBlank 직후 PPU 를 직접 쓰는 루틴: `$CB79-$CBE6`(CHR 로더, 5타일마다 `$F03E`), `$F086-$F0BE`(스크롤 설정).

## 2. 롬 레이아웃 (16KB 뱅크)
| 뱅크 | 내용 |
|---|---|
| 0-6 | 원본 그대로 (+ 각 $BFF9 = 뱅크 번호 표식) |
| 7 | 엔진 코드·표($8000-), kcopy 사본($BFA0) |
| 8-10 | 폰트 1bpp 8x16 (뱅크당 1018자, $8000-$BF9F) + kcopy 사본($BFA0) |
| 11 | 대사 넘침용 (현재 비어 있음) |
| 12 | bank4 복사본 + 한글 dialog_b4 (원래 영역 $8181-$BFF8) |
| 13 | bank6 복사본 + 한글 news_b6 (원래 영역 $9281-$BFF8) |
| 14 | 뉴스 넘침용 (현재 비어 있음) |
| 15 | 고정 (원래 bank7). 엔진 고정부 $FE90-$FFBF |
- 헤더: NES 2.0 byte4 8→16. 매퍼 2, 서브매퍼 2(버스충돌), CHR-RAM 8KB 그대로.
- 원본 bank4/6 은 수정하지 않는다(영문 그대로) → bank4/6 코드가 실행되는 동안 아무 영향 없음. 포인터 표(bank5/6 의 자료)만 새 주소로 바뀜.

## 3. 문자 코드 (= 폰트 인터페이스)
| 바이트 | 의미 |
|---|---|
| 00-36 | 원본 1바이트 문자(8x8). 분할 활성 + 2행 피치 창이면 엔진이 8x16 ASCII 글리프로 바꿔 그림(<VAR> 금액·날짜) |
| 49 | 공백 (번역문의 공백은 이것) |
| 80\|c | 원본 "문자+공백" |
| 4F bb ll hh | 문자열이 뱅크 bb 의 $hhll 로 이어짐(패커가 넘침에 사용) |
| 50-5F xx | **2바이트 글리프**: 엔진 글리프 번호 g = (리드-0x50)*256 + xx |
| FB-FF | 제어(VAR/WAIT/PAGE/줄바꿈/END) 원본 그대로 |
- 엔진 글리프 번호 g ↔ font.bin 순번 i: `g = (i // 1018) * 1024 + i % 1018` (뱅크 8+(g>>10), 주소 $8000+(g&$3FF)*16). 최대 3,054자(3뱅크).
- **font-engineer 가 지킬 것**: (1) `build/font.bin` = 1bpp, 글리프당 16B(위 타일 8행 → 아래 타일 8행, MSB=왼쪽, 1=글자), 순번 연속. (2) `tables/ko_font.tbl` = `5000+i=문자` (2바이트, 코드-0x5000 = font.bin 순번). 코드 시작 0x5000·2바이트는 지금 그대로 유지(패커가 i→g 변환). (3) 글자 수 ≤ 3,054. (4) 공백은 tbl 에 있어도 1바이트 49 가 우선. (5) 8x16 ASCII(숫자·영문·기호) 포함 유지 — <VAR> 출력용 매핑표가 `0-9 A-Z ( ) ' " , $ ! ? - : … . / % &` 와 대체(«→「, »→」, ‥→…)를 찾는다. 없는 기호는 ▶(0x32)뿐.
- 2bpp 변환은 업로드 때 엔진이 함(plane0=0, plane1=글리프 → 원본 폰트와 같은 색).

## 4. 분할(split) [검증]
- $1000 배치: 0x00-0x1F 게임 스프라이트(예약), 0x20-0x3F 한글 슬롯 B(16자), 0x40 빈 타일(감지 스프라이트), 0x41-0x49 $0000 테두리·공백 사본(같은 번호), 0x4A-0xFF 한글 슬롯 A(91자). 합계 107자.
- 활성화(창 y≥16 에 첫 글리프): 슬롯 초기화, 분할 Y = 창 윗행*8-1, 사본 160B 를 게임 큐 작업 5회(32B)로 업로드.
- NMI 시작(`$F962` kdma): 지난 프레임에 분할했으면 PPUCTRL=$01 로 복귀 후 원래 OAM DMA.
- 큐 작업 직후(`$F981` nmi_post, 아직 VBlank): 감지 스프라이트 9개(OAM 55-63, Y=분할Y, 타일 0x40, 뒤)를 RAM OAM 에 쓰고, 오버플로 플래그가 켜져 있으면(지난 프레임) 사전렌더에서 꺼지는 순간으로 동기 → 다시 켜지면(분할 줄) `$2000=$01|$10`. 대기 한도는 241 전에 반드시 끝나도록 (분할Y/32+2)*~29줄.
- 이번 프레임 분할 안 함: 플래그가 이미 꺼짐(NMI 가 사전렌더를 넘김), 렌더링 꺼짐, NMI 가 끊은 메인 스레드 PC 가 직접 PPU 쓰기 루틴 안.
- 비활성화: PPUMASK(`$F197` kmask)로 BG 또는 스프라이트가 꺼질 때 → NMI 가 감지 스프라이트 숨김.
- 비용: 분할 중 NMI 가 분할 줄까지 대기 → 창 윗행 17 이면 프레임 CPU 의 약 55% 를 NMI 가 씀. 대사 출력 속도는 원본과 체감 차 없음(검증 화면).

## 5. 슬롯 할당·업로드 [검증]
- 캐시 KLO/KHI[107] 선형 검색. 미스 → 원형(KNEXT) 할당. 적중이라도 다음 할당 위치에서 40 이내(곧 덮임)면 새 슬롯으로 옮김.
- <PAGE>(창 지우기) 와 재활성화 때 캐시 초기화.
- 글리프 업로드: 폰트 뱅크에서 KBUF(32B, $05C0)로 복사 → 게임 큐 레코드 [02][00][20][FF][KBUF][$1000+T*16] → `$F302` + `$F03E`. 새 글리프 1자당 NMI 1회 추가(타자 출력 2→3프레임/자 수준).
- 버퍼 기록: 타자 모드는 ($89)=위, ($89)+1=아래, `$D948` krows 가 레코드 행 수를 2 로. 이어쓰기 모드는 아래 타일을 버퍼+폭($78)에(첫 글리프 때 아래 행 버퍼를 공백으로).
- 검사기: `kor_build.py text` 가 같은 알고리즘(28칸 자동 줄바꿈, 6줄 스크롤, <PAGE> 초기화)으로 모의해 "보이는 글자의 슬롯이 덮이는" 문자열을 보고(build/kor_text_report.txt). 현재 0.

## 6. 번역 제약 (확정 수치)
- 대사창: 줄당 28칸(한글·영문·숫자 모두 1칸), 6줄/페이지(줄 사이 빈 행 없음 — 아래 타일이 씀).
- **한 화면(창 6줄, 스크롤 포함 보이는 범위)에 동시에 보이는 고유 글자 ≤ 107**, 권장 ≤ 90. 최종 판정은 빌드의 모의 검사(위반 0 이어야 함).
- 텍스트 용량: 뱅크 12 남음 약 1.2KB, 13 약 0.9KB, 넘침 뱅크 11/14 각 16KB (자동 점프 스텁).

## 8. RAM (원본 정적 참조 없음 + 카나리 시험)
- $0600-$06DA KLO/KHI, $06E0-$06ED 변수, $05C0-$05DF KBUF, $05F0-$05F7 KREC. ZP 는 kcopy 가 $10/$11 을 저장 후 사용.

## 9. 위험·미해결
1. 타이틀 데모 카드 한글 미표시(§7).
2. 스프라이트 0x20 이상을 쓰는 장면(전수 미확인)에서 한글 슬롯과 충돌 가능. 감지 스프라이트가 OAM 55-63 을 차지(게임이 그 슬롯을 쓰는 장면이 있으면 충돌).
3. 분할 중 메인 스레드 CPU 감소 → 무거운 장면에서 처리 지연 가능.
4. $0600/$05C0 RAM 은 짧은 구간 카나리만 확인 → QA 장시간 플레이로 확인 필요.
5. 실기: 스프라이트 오버플로 하드웨어 버그 영향 없음(감지 스프라이트가 OAM 연속·같은 Y). 실기 미검증.
6. 원본 세이브스테이트(ralph_call.mss)는 확장 롬에 못 씀(매퍼 상태에 고정뱅크 7 저장) → QA 용 상태는 새 롬에서 다시 만들 것.

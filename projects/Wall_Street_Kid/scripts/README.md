원문은 영어. 툴 호환상 원문 필드 이름이 `ja` 이다. 번역은 `ko`, 메모는 `note` 만 수정한다.
`id`, `ja`, `offset`, `ptr_addr`, `ptr_hi`, `alias_of`, `orig_bytes`, `max_bytes` 는 수정 금지.
덤프: 12블록, 미등록 바이트([XX]) 0개. 원문 그대로 재삽입 후 재덤프하면 텍스트 전부 일치(work/roundtrip.nes, 실행 검증은 아직).
근거 문서: ../analysis.md (표기: 확인/정적/추정).

## 2. 화면 제약 (칸 수 기준)
한글은 8x16 2바이트 엔진이 될 가능성이 높다. 아래 제약은 모두 "칸"(8x8 타일 1개 = 영어 1글자 폭) 기준이며,
8x16 한글 1자가 몇 칸/몇 바이트를 쓰는지는 **미확정**이다(font-engineer/asm-hacker 결정 후 확정). 바이트 제약은 미확정.
잠정 가정: 한글 1자 = 가로 1칸(8px) 또는 2칸(16px). 아래 "칸 수"는 영어 기준 원문 칸 수이므로, 한글을 2칸으로 잡으면 줄당 글자 수가 절반이 된다.

### 대사창 (dialog_b4, news_b6 의 대화 항목) [확인]
- 창: 28칸 x 6줄(높이 12행, 줄 사이 빈 행 1개). 한 페이지 최대 168칸.
- 폭 28에 닿으면 자동으로 다음 줄로 넘어간다(단어를 가리지 않고 글자 단위로 끊음). 그래서 원문에 28글자를 꽉 채워 단어를 붙여 쓴 곳이 많다(`YOUR` + `WALLED` 처럼 공백 없이 붙음). 이는 정상.
- 번역에서는 줄 길이를 직접 관리한다.
  - `\n`(줄바꿈 FE) 을 줄 끝에 쓴다. 28칸을 꽉 채운 줄 뒤에 `\n` 을 또 넣으면 빈 줄이 생길 수 있다(추정, 에뮬 미검증). 줄은 27칸 이하로 쓰고 `\n` 으로 끊거나, 정확히 28칸으로 채우고 `\n` 을 생략하라.
  - 창 높이(6줄)를 넘으면 위로 스크롤된다. 한 페이지는 6줄 이내로 `<WAIT>` / `<PAGE>` 로 나눌 것.
- 제어 토큰(원문과 같은 순서·개수 유지):
  - `<END>` 문자열 끝. 반드시 마지막에 하나.
  - `<WAIT>` 버튼 대기 후 같은 창에 이어서 출력(스크롤됨). 앞뒤에 `\n` 을 둬서 다음 문단 위치를 맞추는 곳이 많다.
  - `<PAGE>` 버튼 대기 후 창을 지우고 다음 페이지. 아내 대화·상점 대사에 주로 쓰임.
  - `<VAR>` 코드가 만든 문자열(금액/날짜/퍼센트)이 들어간다. 길이를 모른다 → 금액은 최대 약 10칸(예: `$2,000,000`), 날짜는 `FRIDAY, JULY 28TH` 형식 최대 약 17칸 (추정). `<VAR>` 앞뒤 어순만 바꿀 수 있고 토큰을 삭제하면 안 된다.
  - `<END>` 만 있고 `<WAIT>`/`<PAGE>` 가 없는 항목은 뒤에 선택 메뉴(예/아니오, (A)(B))가 이어진다. 끝의 빈 줄 여러 개는 메뉴 자리 확보용이므로 유지.
- 허용 문자: 영어 대문자·숫자·`( ) ' " , $ ! ? - : … . / % &` 와 `« »`(장식). 한글은 별도 폰트 확정 후 제한 문자 규칙을 적용(미확정). 번역 중에도 `$`, 숫자, `%` 는 그대로 사용.
- 타일 예산 때문에 한 페이지에 쓰는 고유 음절 수를 제한할 수 있다(analysis.md 7장, 약 100자/페이지 가능성). 확정되면 style.md 에 반영. 지금은 페이지를 짧게 나누는 방향으로 번역.

## 3. alias 처리
`alias_of` 가 있는 항목은 다른 항목과 같은 문자열을 가리키는 포인터이다(예: `SIR, YOU DON'T HAVE ENOUGH CASH` 6곳).
alias 는 `ja`/`ko` 가 없다. 원본 항목의 `ko` 만 번역하면 모두 적용된다. 메뉴 (A)~(D), 인물 이름 등도 같은 원리.
미참조 문자열 `THANK YOU, HONEY.<PAGE>`(0x13626)는 덤프 대상이 아니다(미사용 추정, 삽입하면 사라짐).
탐욕 인코더가 "E"+공백 쌍을 한 바이트(8E)로 바꿔서 원문보다 바이트가 몇 개 줄거나 늘 수 있다(표시는 동일).

## 4. 번역자 규칙
1. `ko` 가 빈 문자열이면 원문 그대로(영어) 출력된다. 번역 전에 삽입하지 말 것.
2. 제어 토큰(`<WAIT>` `<PAGE>` `<END>` `<VAR>`, `\n`)은 원문과 같은 순서·개수로 유지. 단, `\n` 은 줄 길이에 맞게 위치를 바꿔도 된다.
3. 줄 길이 28칸(한글 폭이 확정되면 줄당 글자 수로 환산) 초과 금지. `romkr check --line-width 28 --max-lines 6` 로 검증(한글 폭 확정 후 값 조정).
4. 인명·종목명·분류·용어는 ../glossary.tsv 를 따른다(후보: ../work/glossary_candidates.tsv).
5. 말장난: 종목명(패러디: ATNT=AT&T, YBM=IBM, CHRYER=Chrysler 등)과 뉴스 농담("HA! HA! HA!")은 직역하지 말고 의미가 통하는 말장난으로 의역. 못 살리면 note 에 메모.
6. 같은 문장이 여러 항목에 복제된 곳(117~119 등)은 alias 가 아니므로 각각 번역(같은 번역 사용).
7. 항목마다 `note` 에 화자/상황 힌트가 있다. 힌트는 번역 보조이며, 틀렸다고 판단하면 note 에 수정 의견을 덧붙인다.
8. 기호: `$` `%` 숫자 그대로. 시간·날짜 표기는 style.md 확정 후 통일.
9. 반복 UI 문구(SORRY, HOW MAY I HELP YOU? 등)는 한 번 정한 번역을 일관되게.

## 7. 알려진 문제
- 줄 길이 28 vs 바이트 제약, 한글 폭, 페이지당 고유 음절 수는 font/asm 단계 결정 대기.
- `<VAR>` 최대 길이와 대사창 변형($0404, 폭 22 / 높이 4~6)의 사용처는 미확인. 일부 짧은 창이 있을 수 있어 장문은 QA 필요.
- 항목 96-98, 106(날짜 라벨), 114-116, 120-122 등 일부 note 는 문맥 추정이다.
- 배치 경계는 장면 기준 제안이며, 번역가가 문맥상 필요하면 범위를 조정해도 된다.

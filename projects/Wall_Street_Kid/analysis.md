# Wall Street Kid (USA) — 롬 분석 (1단계)

표기: [확인] 정적+에뮬 확인 / [정적] 코드·데이터 판독, 실행 미검증 / [추정] 추측.
파일 오프셋은 헤더(0x10) 포함, CPU 주소는 $XXXX. spec 생성기: tools/gen_spec.py, 테이블: tables/ja.tbl(내용 영어).

## 1. 플랫폼 / 매퍼 / 확장성
- FC, NES 2.0, 매퍼 2(UxROM), PRG 128KB(16KB x 8), CHR-RAM 8KB. SHA1 caba8f34159eba1ecff38dd7097218c63c240ad7. 체크섬 없음.
- bank0-6 은 $8000 에 전환, bank7 은 $C000 에 고정. 각 뱅크 첫머리 JMP $C010, 끝에 벡터.
- 뱅크 전환 $F066: $07=현재 뱅크, $08=직전 뱅크. 버스충돌 표 $F07E(00..06)에 같은 값을 쓰고, 먼저 $F03E(NMI 대기). [정적]
- 확장: UOROM 256KB(16뱅크)까지 매퍼 교체 없이 가능.
  - 고정 뱅크를 bank15 로 옮기고 헤더 PRG 를 8→16 으로.
  - $F07E 표를 0..14 로 늘려 이전(지금은 바로 뒤 $F085 가 코드).
  - 벡터 유지. [정적]
- 텍스트 출력 $D7B6 은 A=텍스트 뱅크(FF=현재)를 받음 → 텍스트를 새 뱅크로 옮겨도 엔진은 대응 가능.
  래퍼 $C12A(→$DB4A)=bank4, $C12D(→$DB51)=bank6 은 뱅크를 하드코딩. [정적]

## 2. 텍스트 엔진
### 인코딩 (1바이트, 무압축) [확인]
- 코드 = 패턴테이블0 타일 번호. 00-09=0-9, 0A-23=A-Z, 49=공백. 소문자 없음.
- 기호: 24 ( 25 ) 26 ' 27 " 28 ‥(미사용) 29 , 2A $ 2B ! 2C ? 2D - 2E : 2F … 30 . 31 / 32 ▶ 33 « 34 » 35 % 36 &.
- bit7: $80|c = 문자 c 를 쓰고 2칸 전진($D918: AND #$7F, $7B=2). 버퍼가 0x49 로 미리 채워져 있어 결과는 "c␠". DTE·사전·LZ 없음.
- 제어코드(>=$FB, $D90F):
  - FF <END> 끝
  - FE 줄바꿈(모드 bit0 이면 2행 아래)
  - FD <PAGE> 버튼 대기($DB07) 후 창 지우기($DA62)
  - FC <WAIT> 버튼 대기 후 이어서 출력
  - FB <VAR> RAM $038F 문자열(금액·날짜·이름, 코드가 생성)을 삽입($D98D/$D9B3)
- 자동 줄바꿈: x 가 창 폭($8F)에 닿으면 다음 줄로($D87D).
  원문은 28자를 꽉 채운 줄에서 단어를 공백 없이 붙여 둔 곳이 많음(MAKESURE, TOHONEYMOON 등) → 정상.
  번역에서는 줄 길이를 직접 관리해야 함.
- 창 높이를 넘으면 스크롤($D9DB).

### 출력 루틴 [정적/일부 확인]
- $D7B6(A=뱅크) → $D7DF → 루프 $D867, 문자 취득 $D8F8(포인터 $81/$82).
- ZP 파라미터: $83 플래그, $84 x, $85 y, $86 폭, $87 높이(행), $88 모드(bit0 줄간격 2행, bit5 타자음, bit7 이어쓰기).
- 8바이트 디스크립터 [ptr lo][ptr hi][$83][x][y][w][h][$88] 를 $FA6F 로 복사(bank7 에 다수).
- 대사창 기본값($DB71): x2 y17 폭28 높이12 모드0x21 → 28자 x 6줄, 줄 사이 빈 행. 에뮬 확인.
  $0404 에 따라 x8 y25/23 폭22 높이4/6 변형 있음(용도 미확인).
- 한 줄을 $032B 버퍼에 모아 $0323 전송 리스트 → NMI 에서 기록. 1글자 = 8x8 1타일. 타자 출력, A 를 누르는 동안 가속.

## 4. 폰트 / CHR
- 폰트 원본: bank0 $A365 = 파일 0x2375, 1bpp 8x8, 55타일(코드 0x00-0x36).
  - bank0 $8010 업로드 표 첫 항목 "37 65 A3 00 00"(개수, 소스, VRAM $0000)으로 CHR-RAM 에 2bpp(plane1=0)로 올림. 에뮬 확인.
  - 표 형식 [개수][src][dst] 는 추정.
- 같은 글리프의 2bpp 사본이 bank2 0x90A3 / 0xA0AB 에 있음(용도 미확인).
- 고정폭, VWF 없음.
- 0x37-0x40 은 기호 타일(폰트 아님). 패스워드 화면은 0x00-0x40 의 65타일을 문자로 씀(문자표 0x1E874).
- 0x41-0x48 테두리, 0x49 빈 타일.
- CHR 예산(랄프 전화 장면 실측) [확인]:
  - BG $0000 은 빈 타일 거의 없음. 0x60-0xFF 는 장면 그림(장면마다 교체).
  - SPR $1000 은 256 중 227 이 빈 타일. 스프라이트는 화면 상단에만 있음.
  - PPUCTRL: BG=$0000, SPR=$1000, 8x8 스프라이트.

## 7. 한글화 난점
1. 한 화면 동시 글자 수 [확인]: 대사창 28 x 6 = 168칸. 8x16 이면 최악 336타일.
2. 줄 간격 [확인]: 대사창이 이미 2행 피치 → 8x16 한글을 레이아웃 변경 없이 넣을 수 있음.
3. 타일 예산:
   - BG 테이블0 은 꽉 참 [확인]. SPR 테이블 $1000 에 227타일 여유 [확인].
   - UxROM 은 IRQ 가 없으니 스프라이트0 히트 또는 타이밍으로 대사창 위에서 BG 패턴테이블을 $1000 으로 전환하면 약 200타일 확보 가능 [추정, asm].
   - 그러면 페이지당 고유 음절 약 100자까지. 번역에 페이지당 글자 수 제한과 <PAGE> 분할 필요.
   - 대안: 8x8 한글, 또는 최후 수단으로 매퍼 교체.
4. 동적 업로드 [추정]: CHR-RAM 이라 출력할 때 글리프를 올리면 됨. 음절당 32B → NMI 예산상 1-3자/프레임. 타자 출력이라 체감 지연 적음.
5. 코드 공간 [정적]:
   - 0x37-0x48, 0x4A-0x7F 는 텍스트에 안 쓰임 → 2바이트 리드 후보.
   - 0x80-0xFA 는 "문자+공백", 0xFB-0xFF 는 제어 → 엔진 개조 시 정리.
6. ROM 공간 [정적]: 영어만으로 bank4 91%, bank6 92%. 2바이트 한글이면 부족.
   - 256KB 확장 + 새 뱅크로 이전 + $C12A/$C12D·스크립트에 뱅크 정보 추가.
   - 분리 포인터는 16비트라 같은 뱅크 안에서만 이동 가능.
7. 고정폭/정렬 문자열: 메뉴(bank7 267B, 뒤가 코드), 요일 3B, CASH:/STOCKS: 5/7B, 매매화면 틀(숫자 열 위치), 정보화면 종목명(가운데 정렬용 앞 공백).
8. 위험요소:
   - 버스충돌 표 $F07E.
   - 고정뱅크 여유 330B.
   - 패스워드 화면이 0x00-0x40 전부 사용.
   - 타이틀 전용 타일.
   - 스태프 롤 별도 형식.
   - 단독 포인터를 버렸으므로 놓친 포인터가 있으면 해당 대사가 깨짐(QA 확인 필요).
   - 탐욕 인코더가 "E"+공백(0E 49)을 8E 로 바꿔 쓰므로, 원문 바이트 배열과 달라질 수 있음(표시는 같음).
